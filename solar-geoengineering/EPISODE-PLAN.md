# ☀️ Episode Plan — Solar Geoengineering

## Working Title
"Drawingshade: Can Open-Source Code Democratize Solar Geoengineering?"

## Episode Arc

### Act 1: The Simulation Problem
- SRM is the most researched, least democratic climate intervention
- The tools for simulating SRM are largely proprietary or legacy
- What happens when only a few institutions can model the planet's thermostat?

### Act 2: The Code We Found
- PCMDI/pcmdi_metrics: 133 stars, institutional burst pattern
- AM3: Frozen Fortran from 2015 — the "classic" SRM model
- Arctic impact codes: Single-use academic repos that go dormant
- The evaluation-vs-simulation gap: We can score models but can't easily run them

### Act 3: The Democratization Question
- Could interactive, open-source SRM simulation change the political conversation?
- What would a "Google Maps for solar geoengineering" look like?
- The governance implications of code accessibility

## Key Segments
1. **"Who Models the Sun?"** — The institutional landscape of SRM simulation
2. **"The Python Gap"** — Why modern open-source hasn't reached SRM
3. **"The Arctic Question"** — Regional impacts and whose code gets visible
4. **"What If It Were Open?"** — Counterfactual: an open-source SRM simulator

## Production Notes
- **Duration estimate:** 35–45 minutes
- **Tone:** Analytical, slightly provocative
- **Caveat:** Avoid being anti-SRM. The goal is to examine *who controls the tools*, not whether SRM is good or bad.
- **Music suggestion:** Ambient/spacey for SRM "perception" segments
