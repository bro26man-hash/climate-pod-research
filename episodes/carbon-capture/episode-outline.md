# 🌱 Carbon Capture (CDR) — Episode Outline

**Branch:** `carbon-capture`
**Format:** Modular, ~40–50 min episode

---

## Scene 1 — The Scale-Up Paradox (Cold Open)
- DAC/CDR is pointless at demo scale; it only matters at *gigatonne* scale.
- Yet the open-source side of CDR is a handful of tiny repos — the opposite of scale.
- Pose the question: "Can open source even touch the $1000/ton barrier?"

## Scene 2 — What Open Source Actually Offers (A Field Survey)
- **The directory layer** — `open-sustainable-technology` (2,546★): the best found "map" of the whole climate-oss territory. Use it as a discovery lens.
- **The verification layer** — `carbonplan/forest-risks` + `cdr-database`: science already happened, now rewiring carbon markets. Even "dead" repos can be policy-shaping.
- **The materials layer** — DFT sorbent screening (tjz21 peroxovanadate/titanate, Aug 2026): brand-new, pre-print-adjacent, directionally promising.
- **The process land side** — `ClimaLand.jl`: quietly active soil-carbon module.

## Scene 3 — Two Modes of Open CDR
- Mode A — **maintenance/verification** (CarbonPlan): published, policy-influential, no more code. The "done and done" story.
- Mode B — **materials discovery** (open DFT sorbents): the August 2026 burst; embryonic, lots of potential, zero deploy.
- Mode C — **DIY / open-hardware** (electro-swing-dacc): grassroots, low-cost, far from commercial.
- Contrast these with the closed industrial front-runners (Climeworks, Heirloom, Carbon Engineering) — the real scale-ups are IP-locked.

## Scene 4 — Can Open Source Break the Cost Barrier?
- Honest assessment: open source is not driving the cost curve today. The $1000→$100/ton drop came from engineering, not github.
- But: open materials screening *could* accelerate sorbent discovery if the Aug 2026 cluster grows — the one credible open contribution path to cost reduction.
- BIM (big implausible moment): open computation shortening the materials cycle. Evidence: thin but directionally logical.

## Scene 5 — The Forest/Side-quest
- forest-risks: how a 35-star repo shaped carbon-market methodology. Proof that open CDR code can punch above its weight via *standards/verification*, not capture hardware.

## Out-Cue / Discussion Questions
1. Is open-source CRO a credible path to cheaper DAC, or just a hobbyist mirror of industrial work?
2. Should CarbonPlan-style verification tools be the model for "making open CDR matter"?
3. Does a DIY/open-hardware DAC movement have a credible path, or is it inevitably规范性?
